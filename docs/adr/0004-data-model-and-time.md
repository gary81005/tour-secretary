# 0004 資料模型與時間

- 狀態：已採用（2026-11-04）；M1 實作細節補充於 2026-11-06

## 背景

使用者實際的行程表（`docs/samples/東北秘境探險.xlsx`）大多寫模糊時段（上午／中午／下午／晚上），一個項目常包含多個地點，並且寫了不少備案與旅伴限制。

## 決策

- 結構：**Trip → Day → Item**；名詞定義見 `CONTEXT.md`。
- **Item** 必填 TimeSlot（清晨／上午／中午／下午／傍晚／晚上／整天），選填開始／結束時間；必填 Category（景點、餐食、交通、住宿、購物、提醒）。
- Item 對應 **0 到多個有序 Place**；M1／M2 只存文字，M3 才解析成地圖地點。
- 正式結構：**Stay**（住宿）、**TripNote**（提醒事項）、**Fallback**（掛在 Item 下的備案）、**TravelerConstraint**（旅伴限制）。
- 延後：候選住宿比價、預算記帳。
- **時間存當地時間 + IANA 時區**（時區放在 Day），畫面一律顯示當地時間。

## 理由

- 行程的本質是「當地幾點在哪裡」；存 UTC 再依裝置換算，出發前與抵達後看到的時間會不同。
- 只有填了精確時間的 Item 才觸發落後提醒，避免模糊時段造成誤報。
- Fallback 與 TravelerConstraint 是臨時調整（M6）與 AI 提案（M7）最重要的輸入。

## M1 實作細節

資料表見 `supabase/migrations/`；純邏輯在 `src/lib/trip/`（有測試）。

### 天與日期

- `days` 一天一筆，以 `(trip_id, date)` 唯一；「第 N 天」是依日期排序的序號，不存資料庫。唯一鍵是 `deferrable`，整趟平移時可以一次改完所有日期。
- `days.timezone` 為 null 表示沿用 `trips.default_timezone`；時區名稱由 trigger 驗證。
- 一趟行程最多 60 天（`trips_date_range`）。
- 起訖日與天的日期**不能直接改**，只能透過四個 RPC，天數才不會和日期範圍脫節（Q15）：
  - `shift_trip`：整趟平移到新的出發日，每天的內容跟著第 N 天移動；平移天數在函式內用當下的出發日計算。
  - `set_trip_dates`：修改起訖日，以日期對應；要刪的天還有項目時整筆擋下，並回傳那些日期。
  - `insert_day_after` / `delete_day`：之後的日期往後／往前移一天。
- 平移、插入一天、刪除一天時，住宿日期跟著天一起調整；只住被刪那一晚的住宿改成軟刪除。
- `set_trip_dates` **不調整住宿**：縮短範圍後，範圍外的住宿保留原日期，住宿分頁標示「不在行程日期內」（Q23：範圍外只提醒），由使用者自己改或刪。

### 時段與排序

- 時段的預設時間範圍：清晨 05–08、上午 08–11、中午 11–14、下午 14–17、傍晚 17–19、晚上 19–24，「整天」排最前（`src/lib/trip/time-slot.ts`）。
- 填了開始時間自動帶入時段，使用者可以改回來；00:00–05:00 歸到清晨。不支援跨午夜（結束時間要晚於開始時間）。
- 同一天依時段排序；同時段內，有精確時間的排前面並照時間排，沒有時間的照 `position`（手動順序）。
- 只有沒填時間的項目可以拖拉；拖到別的時段就改成那個時段（`reorder_items`）。

### 項目、地點、備案

- `save_item` 在同一個 transaction 寫入項目，並整批替換它的地點與備案；新項目或換了天／時段的項目排到該時段最後。
- 地點與備案沒有軟刪除，隨項目一起存。
- 連結只接受 http(s)：資料庫 check constraint + 顯示前的 `isSafeHttpUrl()`。

### 軟刪除（Q13、Q14）

- 有 `deleted_at`：`trips`（進垃圾桶）、`items`、`stays`、`trip_notes`、`traveler_constraints`（刪除後提示框可以「復原」）。
- 超過 30 天由 `pg_cron` 每天執行 `purge_deleted_rows()` 永久刪除。
- 沒有軟刪除：`days`（刪除前確認）、`item_places`、`fallbacks`（隨項目存）、`trip_members`。
- 天被刪除時（`delete_day`、`set_trip_dates`），那一天**已經軟刪除**的項目會隨著天一起永久刪除，不再能復原；未刪除的項目會先擋下（`set_trip_dates`）或在確認對話框提醒（`delete_day`）。
