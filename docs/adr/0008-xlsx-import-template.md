# 0008 xlsx 匯入範本

- 狀態：已採用（2026-11-04）；M2 細節於 2026-11-06 定案

## 背景

使用者現有的行程表（`docs/samples/東北秘境探險.xlsx`）把七個區塊放在同一張工作表；每日行程是**橫向**排列：第 1 列日期、第 2 列城市、每天 2 欄（時段 | 內容），第 7 列整列空白後才是提醒事項、住宿規劃等其他區塊。時段欄寫法不一（「約17:00」「早上」「晚餐」「傍晚／晚上」「住宿」），內容欄常有多行。

## 決策

- 自訂標準範本，以 exceljs 依規則解析（只用動態 `import('exceljs')` 載入）。
- 第一張工作表**沿用使用者的橫向格式**：第 1 列日期、第 2 列城市、每天 2 欄（時段 | 內容）。
- 住宿、提醒事項、備案、旅伴限制各自一張結構化的工作表。
- 匯入後先在畫面上預覽、修正，確認後才存檔。
- 格式不固定的檔案（例如目前這份範例第 14 列以後的區塊）交給 M7 的 AI 匯入處理。

## M2 細節

### 入口與模式（Q1、Q12）

- **新建**：首頁「新增行程」旁的「匯入 xlsx」。
- **既有行程**：行程選單的「匯入 xlsx」，再選「附加」或「覆蓋」。
- 流程：上傳 → 選模式（既有行程）→ 預覽 → 確認。目前所有成員都能匯入；覆蓋是否只限 owner，見 ADR 0005「M5 之前要處理」。

### 解析（Q2–Q8、Q11）

在瀏覽器解析，檔案不上傳；上限 5 MB。純邏輯在 `src/lib/import/`（有測試）。錯誤與警告都標到「工作表!儲存格」。

- **第一張工作表**（不看名稱）：第 1 列日期、第 2 列城市、每天 2 欄；從第 3 列讀到**第一個整列空白**為止，之後還有內容時提示「第 N 列以後未匯入」。所以使用者的舊檔可以直接匯入每日行程。
- **日期**：Excel 日期值，或含年份的 `YYYY/M/D`、`YYYY-MM-DD` 文字；必須遞增、不能重複，總長度 ≤ 60 天；中間跳過的日期建立成空白的一天。
- **城市**：合併儲存格跨幾天就套用到那幾天。
- **時段欄**，依序比對：
  1. 時段名稱：整天、清晨、上午、中午、下午、傍晚、晚上。
  2. 時間 `HH:MM` 或 `HH:MM–HH:MM`（可有「約」「左右」、全形冒號）：填入精確時間，時段依 ADR 0004 規則自動帶入。
  3. 同義詞：早上→上午；早餐→清晨＋餐食、午餐→中午＋餐食、晚餐→晚上＋餐食；夜晚→晚上；「A／B」取第一個；住宿→晚上＋住宿；提醒→整天＋提醒。
  4. 空白或認不出來：歸到「整天」，標成**警告**。
- **類別**：同義詞決定的優先；否則依關鍵字推測（交通：新幹線、JR、巴士、搭、前往、機場、接駁；餐食：餐、用餐、料理；住宿：入住、退房、Check-in；購物：購物、逛街、伴手禮），都沒有就是「景點」，推測的標成警告。
- **內容欄**：第一行（去掉結尾的「；」「，」）是標題，其餘各行是說明；標題超過 200 字時截斷，全文放進說明。**不拆地點**（M3 用地圖搜尋補）。
- **其他工作表**（同名才讀，第 1 列是標題列，`*` 必填；只有標題列、沒有資料的工作表當作沒有）：
  - 住宿：名稱* ｜入住日* ｜退房日* ｜地址｜狀態（候選／已預訂／已付款，空白＝候選）｜確認碼｜連結｜備註
  - 提醒事項：主題* ｜內容
  - 備案：日期* ｜項目標題* ｜條件｜替代方案*
  - 旅伴限制：類型*（飲食／體力／行動／偏好／其他）｜對象｜內容*
- **備案比對**：用「日期＋標題」先比對檔案裡的項目；附加模式再比對行程裡同一天的既有項目（Q16）；檔案的項目已存在（預設不匯入）時，掛到既有的那一個。對不到的標成錯誤，可以在預覽改掛到別的項目或略過。

### 預覽（Q9）

- **錯誤**（日期不合法、必填空白）擋住匯入，修檔案後重新上傳。
- **警告**可以在預覽處理：改時段／類別、勾掉不要匯入的列、改掛備案；新建時另可改行程名稱（預設為檔名）與預設時區（預設 Asia/Tokyo）。
- 文字內容不在預覽改，匯入後用一般的編輯面板。

### 附加與覆蓋（Q13、Q14、Q16）

|                          | 新建       | 附加                           | 覆蓋                             |
| ------------------------ | ---------- | ------------------------------ | -------------------------------- |
| 檔案日期超出行程範圍     | —          | 自動延長（≤ 60 天），不會縮短  | 同左                             |
| 項目                     | 全部建立   | 加到同一天、同時段的最後       | 檔案涵蓋的日期，既有項目整天替換 |
| 城市                     | 檔案的值   | 只填原本空白的天               | 檔案有寫的就覆蓋                 |
| 住宿／提醒事項／旅伴限制 | 全部建立   | 加入                           | 檔案那張工作表有資料才整批替換   |
| 行程名稱、預設時區       | 預覽中設定 | 不變；延長的天用行程的預設時區 | 同左                             |

- **重複資料**（附加）：項目＝同日期＋同標題；住宿＝同名稱＋同入住／退房日；提醒事項＝同主題；旅伴限制＝同類型＋同內容。預設不勾，預覽標「已存在」，可以手動勾回來。
- 被替換的資料一律**軟刪除**。
- 範本一律附上住宿等工作表；只填「行程」就覆蓋時，留白的工作表不會清空既有資料（2026-11-10 review 後調整）。

### 存檔與復原（Q11、Q15）

- 確認後送結構化 JSON 到 Server Action，zod 再驗一次，呼叫 `import_trip` RPC：同一個 transaction 寫入所有資料，失敗時全部不留。完成後導到行程（新建時第 1 天，否則檔案的第一個日期）。
- 覆蓋前有確認對話框，列出將取代的天數與筆數。
- 附加／覆蓋每次記一筆 `trip_imports`：新增的 id、被替換的 id、原本的城市與起訖日。新建行程的匯入不記錄，要復原就把整趟移到垃圾桶。
- 提示框與行程選單提供「復原上次匯入」，**30 天內且尚未再次匯入**時可用（`undo_import`）。只有行程最近一次的匯入能復原；它復原之後，更早的匯入也不能再復原：
  - 這次新增的項目、住宿、提醒事項、旅伴限制改成軟刪除；新增到既有項目上的備案刪除。
  - 被替換的資料還原、城市改回原值。
  - 延長出來的天從最外側往內刪，遇到還有其他項目的天就停止，起訖日跟著調整。

### 範本（Q10）

匯入頁的「下載範本」由瀏覽器用 exceljs 即時產生，選項永遠與程式一致：

- 5 張資料工作表（行程、住宿、提醒事項、備案、旅伴限制），時段、狀態、類型欄有下拉選單。
- 第一張附 3 天東北行程範例。
- 最後一張「說明」寫填寫規則。
