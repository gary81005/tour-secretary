# 0010 PWA 與離線

- 狀態：已採用（2026-11-04）；M4 細節於 2026-11-12 定案

## 決策

- 產品形態是 **PWA**：可加到主畫面，使用 Web Push、定位。不做原生 App。
- 離線支援範圍：**目前這趟旅程可以離線唯讀**（行程、地址、已查過的交通指南），編輯需要網路。不做完整離線同步。

## 理由

- 地下鐵與山區常沒有訊號，能看就夠；完整離線同步的衝突處理成本過高。
- iOS 16.4 以上加到主畫面後才能收 Web Push，需在 UI 引導使用者安裝。

## M4 細節

### 「現在／下一站」（Q1、Q2、Q8、Q9）

- 行程分頁選到「今天」時，項目列表上方顯示「現在／下一站」卡片；首頁進行中的行程卡片也顯示現在與下一站（只有標題）。
- 進度用**手動完成**：`items.done_at` 記完成時間，旅伴同步看到（不記是誰按的）。只有「完成」，沒有「跳過」（沒去的項目屬於臨時事件，由 M6 的調整工具處理）。
- 「現在」卡片有「完成」按鈕；今天與之前的項目卡片左側有勾選框，可以補勾或取消。未來的天不顯示勾選框。
- **現在**：今天第一個未完成的項目；**下一站**：再下一個未完成的項目，附交通指南。
- 沒有下一個項目時，下一站是「今晚住」（已預訂／已付款的優先）：住宿沒連結地點時仍顯示，用填的地址或名稱導航，不算移動時間；今晚沒有住宿（例如最後一天）時顯示「今天沒有下一站了」。
- 今天全部完成時，卡片改成「今天的行程都完成了」，接「今晚住」與回住宿的導航。
- 超過時間仍未完成不提醒（M6 的落後提醒處理）。

### 交通指南（Q3、Q10）

- 移動時間與「查電車」沿用 M3（ADR 0006 Q9）。
- 「導航」按鈕：Google 地圖路線連結只帶目的地，起點由 Google 地圖用手機目前位置，不需要定位權限，也不呼叫 API。韓國改開 KakaoMap／Naver Map 搜尋目的地（ADR 0006 Q13）。
- 「建議出發時間」：下一站有精確時間，且步行 30 分鐘以內時才顯示＝開始時間 − 步行時間 − 5 分鐘。需要搭車的段算不出電車時間，不顯示。
- 不用手機定位即時計算（M6 落後提醒再一起做）。

### 離線唯讀（Q4、Q5、Q11、Q12）

- **本機快照**：線上打開「進行中或 7 天內出發」的行程時，自動把行程資料（天、項目與完成狀態、地點、備案、住宿、提醒事項、旅伴限制）存進瀏覽器的 IndexedDB。
- Google 的資料（營業時間、Google 地址、移動時間）不存（服務條款），離線時不顯示；「在 Google 地圖開啟」等連結保留，有網路時可用。
- **Service Worker** 只快取 app 外殼與「離線行程」頁。沒有網路時，所有頁面導覽改顯示離線行程頁：存了多趟時先列出來選，只有一趟直接打開。
- 離線行程頁全部唯讀：每一天（可切換）、「現在／下一站」、住宿、提醒事項、旅伴限制；「完成」按鈕停用並標示需要網路。頂端顯示「離線中・資料更新於 …」。
- 清除：行程結束隔天、不再是成員或行程進垃圾桶時刪除該快照（線上打開首頁時檢查）；登出時清除全部快照與 Service Worker 快取，避免共用手機外洩。
- 訊號不穩時開啟 Next 的 `experimental.useOffline`：斷線時導覽與 Server Action 等網路恢復後自動重試，頂端提示「離線中」並連到離線行程頁（Q13）。
- 實作（第 5 步）：
  - Service Worker 自己寫（`public/sw.js`），不用套件：只快取 `/offline` 的 HTML、它用到的 `/_next/static` 檔案與圖示；安裝時與每次打開 app 時更新（最多每 10 分鐘一次），全部抓到才替換，避免 HTML 與檔案版本對不上。
  - 頁面導覽先連網路；連不上時轉址到 `/offline`（網址也換掉，避免 Next 在別的網址上載入離線頁）。
  - 離線頁在 `(app)` 外面、不需要登入、完全靜態，快取的 HTML 不含個資；資料從 IndexedDB 讀。
  - 「離線中」橫幅與離線頁的連結用 `<a>` 整頁導覽，讓 Service Worker 回應；`<Link>` 的 soft navigation 離線時只會一直等待。
  - 只在正式版註冊 Service Worker（開發模式的熱更新會和快取互相干擾）；離線行為用 `next build && next start` 測。
  - 登出時刪除 `tour-secretary-` 開頭的快取（`clearOfflineData()`）。
- 實作（第 6 步）：
  - 快照用瀏覽器原生的 IndexedDB（`src/lib/offline/snapshot-store.ts`），不加套件：資料庫 `tour-secretary`，一趟行程一筆，key 是 tripId。
  - 行程 layout 判斷「進行中或 7 天內出發」後，在 `<Suspense>` 裡查整趟行程（`src/data/offline.ts`），交給 Client Component 存進 IndexedDB。layout 只在進入行程時執行，切換分頁不會重查；編輯後的 `refresh()` 會帶來新快照，完成狀態也跟著更新。
  - 快照格式（`src/lib/offline/snapshot.ts`）逐欄挑選，不含座標；記錄伺服器讀取時間（離線頁的「資料更新於」），已存的資料比較新時不覆蓋。格式改變時把 `OFFLINE_SNAPSHOT_VERSION` 加一，舊版本讀到就丟掉。
  - 清除：線上打開首頁時只留下「仍是成員、未刪除、進行中或 7 天內出發」的快照；離線讀取時也會刪掉過期的（行程結束隔天）；登出時刪除整個資料庫。

### 安裝（Q6、Q7、Q14）

- Web App Manifest：名稱「旅遊秘書」、青綠主題色、192／512 與 maskable 圖示（先由 `public/trip.png` 產生，之後換高解析版）。
- 首頁的安裝提示卡：只在手機、尚未安裝（`display-mode: standalone`）時顯示，按「不用了」後這支手機不再顯示。iOS 顯示「分享 → 加入主畫面」步驟；Android／Chrome 用 `beforeinstallprompt` 顯示「安裝」按鈕。行程進行中或 7 天內出發時，加一句離線的好處。
- Web Push 留到 M6（落後提醒才有要推的內容）。
