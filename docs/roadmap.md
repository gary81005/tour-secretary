# Roadmap

每個 milestone 開一個 branch；開始前先針對該階段細節確認需求，完成後跑 build / lint / test 再 review。

|        | 內容                                                                                                                                                       | 狀態    |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| **M0** | 基礎建設：shadcn/ui + Tailwind、Supabase SSR、next-intl、Prettier / ESLint / Vitest、React Compiler、嚴格 TS、文件                                         | ✅ 完成 |
| **M1** | 登入（Email 驗證碼／連結 + Google OAuth）、行程增刪改查與垃圾桶、手動編輯（天 → 項目，含時段、類別、地點、備案、時區、拖拉排序）、住宿、提醒事項、旅伴限制 | ✅ 完成 |
| **M2** | xlsx 範本匯入（新建／附加／覆蓋、預覽、復原上次匯入；ADR 0008）                                                                                            | ✅ 完成 |
| **M3** | MapProvider（Google）：地點搜尋與連結、「幫我找地點」、營業時間、Google 地址、項目間移動時間、當天路線（ADR 0006）                                         | ✅ 完成 |
| **M4** | 旅途模式：「現在／下一站」與完成進度、交通指南（導航、建議出發時間）、PWA 安裝、離線唯讀（ADR 0010）                                                       | ✅ 完成 |
| **M5** | 旅伴邀請與權限：邀請連結、旅伴名單與退出、主辦人專屬操作、名稱設定、SQL 回歸測試（ADR 0005）                                                               | 進行中  |
| **M6** | 定位落後提醒 + 手動回報臨時事件（不用 AI 的調整工具）                                                                                                      |         |
| **M7** | Claude：從零規劃對話、非固定格式匯入、臨時事件自動提案                                                                                                     |         |

之後再考慮：候選住宿比價、預算記帳、en-US 等其他語系、韓國 Kakao provider、完整離線編輯。

M1 留到之後處理：

- 接自己的 SMTP（例如 Resend）：目前 Supabase 內建寄信只寄給專案的團隊成員，旅伴用 Email 登入可能收不到信。接好後拿掉邀請頁 Email 下方「建議用 Google 登入」的註明（ADR 0005 Q10）。
- 跨午夜的項目（夜車、紅眼班機）目前只能填開始時間。
- 沒有 `global-error.tsx`：root layout 本身出錯時是 Next 預設頁面。

M2 留到之後處理：

- 匯入不拆地點（ADR 0008 Q5）：M3 改由項目表單的「幫我找地點」逐項連結；沒有批次連結整個行程的功能。
- 格式不固定的行程表（例如範例檔第 14 列以後的區塊）交給 M7 的 AI 匯入。
- 匯入資料超過 Server Action 的 1 MB 上限時只在預覽擋下，提示拆檔分次附加；實際遇到再考慮調高 `serverActions.bodySizeLimit`。

M3 留到之後處理：

- 伺服器快取（營業時間、地址、移動時間）只在各 Vercel 執行個體的記憶體裡，不一定命中；真正擋住費用的是 Google Cloud 的每日上限（`docs/setup/google-maps.md`）。用量變大時再考慮共用快取（服務條款允許的範圍內）。
- 座標超過 30 天由每天的清理排程清掉，下次存檔時才重新查；沒有排程主動補查。M6 定位提醒需要座標時再決定是否補。
- `GetPlace` 每日上限維持 100（存檔查座標、營業時間、地址共用）。上線後觀察用量，常常打滿再調高或減少查詢（例如另一種語言的地址等按切換時才查）。
- 日本的大眾運輸算不出來，只附「查電車」連結；M4 的交通指南若要顯示電車時間，需要另找資料來源。
- 拖拉排序後，新的路段要等伺服器重新查好才有移動時間（約 1 秒），之前只顯示「查電車」。
- 韓國：KakaoMap／Naver Map 只用目的地名稱搜尋，不能直接開路線（服務條款不允許把 Google 的座標交給其他地圖）；Kakao provider 列在「之後再考慮」，接上後可以用 Kakao 自己的座標開路線。

M4 留到之後處理：

- 建議出發時間只在步行 30 分鐘內顯示；需要搭車的段（日本的電車）算不出時間，只附「查電車」。
- 離線快照只在線上打開行程時存（首頁不存）；出發前沒打開過行程，離線時就看不到。
- 離線時沒有移動時間、營業時間與 Google 地址（服務條款不能存），「查電車」與導航要靠手機的地圖 App。
- 「現在／下一站」的移動時間只查當天相鄰項目之間的段：亂序打勾（例如先勾了中間的項目）時，「現在」到「下一站」這段沒查過，只顯示「查電車」與導航，沒有移動時間與建議出發時間。
- 離線時按「完成」會排隊等網路恢復（`experimental.useOffline`）；這時點「離線中」橫幅的「看離線行程」是整頁導覽，排隊中的變更會丟掉，也沒有提示。
- Service Worker 只在正式版註冊，快取名稱的前綴在 `public/sw.js` 與 `src/lib/offline/clear.ts` 各寫一次，改名時兩邊要一起改。
- App 圖示由 `public/trip.png` 產生，之後換成高解析版。
- Web Push（落後提醒）留到 M6；iOS 要加到主畫面後才能收。
