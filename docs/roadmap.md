# Roadmap

每個 milestone 開一個 branch；開始前先針對該階段細節確認需求，完成後跑 build / lint / test 再 review。

|        | 內容                                                                                                                                                       | 狀態    |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| **M0** | 基礎建設：shadcn/ui + Tailwind、Supabase SSR、next-intl、Prettier / ESLint / Vitest、React Compiler、嚴格 TS、文件                                         | ✅ 完成 |
| **M1** | 登入（Email 驗證碼／連結 + Google OAuth）、行程增刪改查與垃圾桶、手動編輯（天 → 項目，含時段、類別、地點、備案、時區、拖拉排序）、住宿、提醒事項、旅伴限制 | ✅ 完成 |
| **M2** | xlsx 範本匯入（新建／附加／覆蓋、預覽、復原上次匯入；ADR 0008）                                                                                            | ✅ 完成 |
| **M3** | MapProvider（Google）：地點搜尋與連結、「幫我找地點」、營業時間、Google 地址、項目間移動時間、當天路線（ADR 0006）                                         | ✅ 完成 |
| **M4** | 旅途模式：「現在／下一站」、交通指南、PWA、離線唯讀                                                                                                        |         |
| **M5** | 旅伴邀請與權限                                                                                                                                             |         |
| **M6** | 定位落後提醒 + 手動回報臨時事件（不用 AI 的調整工具）                                                                                                      |         |
| **M7** | Claude：從零規劃對話、非固定格式匯入、臨時事件自動提案                                                                                                     |         |

之後再考慮：候選住宿比價、預算記帳、en-US 等其他語系、韓國 Kakao provider、完整離線編輯。

M1 留到之後處理（細節見 ADR 0005「M5 之前要處理」）：

- M5 前：接自己的 SMTP；決定哪些操作只有 owner 能做（移到垃圾桶、平移、修改起訖日、增刪天、匯入覆蓋與復原），policy 與日期函式一起改。
- 跨午夜的項目（夜車、紅眼班機）目前只能填開始時間。
- 沒有 `global-error.tsx`：root layout 本身出錯時是 Next 預設頁面。

M2 留到之後處理：

- 匯入不拆地點（ADR 0008 Q5）：M3 改由項目表單的「幫我找地點」逐項連結；沒有批次連結整個行程的功能。
- 格式不固定的行程表（例如範例檔第 14 列以後的區塊）交給 M7 的 AI 匯入。
- 匯入資料超過 Server Action 的 1 MB 上限時只在預覽擋下，提示拆檔分次附加；實際遇到再考慮調高 `serverActions.bodySizeLimit`。
- M5 前：`trip_imports.created_at` 是交易開始時間（`now()`），兩位旅伴幾乎同時匯入時，「最近一次匯入」可能判斷顛倒；改用取得行程鎖之後的時間或序號，與 owner 權限一起改。`previous_start_date` / `previous_end_date` 目前沒有用到（復原用剩下的天重算起訖日），一併決定保留或移除。
- M5 前：migration 只在 Docker 手動驗證過（第 4 步的 9 個情境，加上 M3 修正的「附加匯入時選填的工作表是 null」），把它們整理成 repo 裡的 SQL 測試腳本，之後改 migration 才有回歸測試。

M3 留到之後處理：

- 伺服器快取（營業時間、地址、移動時間）只在各 Vercel 執行個體的記憶體裡，不一定命中；真正擋住費用的是 Google Cloud 的每日上限（`docs/setup/google-maps.md`）。用量變大時再考慮共用快取（服務條款允許的範圍內）。
- 座標超過 30 天只在下次存檔時重新查，不跑背景排程；過期的座標只影響搜尋偏向與韓國的 KakaoMap 路線連結。M6 定位提醒需要座標時再決定是否補排程。
- 日本的大眾運輸算不出來，只附「查電車」連結；M4 的交通指南若要顯示電車時間，需要另找資料來源。
- 拖拉排序後，新的路段要等伺服器重新查好才有移動時間（約 1 秒），之前只顯示「查電車」。
- 韓國：Naver Map 只開目的地（路線網址沒有公開規格）；Kakao provider 列在「之後再考慮」。
